# Архитектура меню и навигации — MyTravel.Lab

Версия: v1 (согласовано с UX-спецификацией продукта).  
Связанные документы: `USER_FLOWS.md`, `MVP_BOT_SPEC.md`, `BOT_PERSONA.md`.

## Принцип

Не дублировать функции между:

1. **Нижнее постоянное меню** — продуктовая навигация.
2. **Burger-команды Telegram** — технический аварийный слой.
3. **Inline-кнопки** — следующий лучший шаг в текущем сценарии.

## 1. Нижнее меню (Reply Keyboard)

| Кнопка | Назначение |
|--------|------------|
| 🧭 Текущая поездка | Вернуться к активному сценарию / последнему незавершённому шагу |
| 📂 Мои поездки | Список поездок со статусами |
| ✨ Новая поездка | Создать новую поездку |
| ℹ️ Как работает | Ценность продукта и возможности (не дублировать с /help) |

**Не включать в нижнее меню:** Помощь (есть `/help`), дубли «Новая поездка» / «Мои поездки» в burger.

## 2. Burger-команды

| Команда | Назначение |
|---------|------------|
| `/start` | Перезапуск бота |
| `/help` | Помощь, если застрял |
| `/cancel` | Отменить текущий ввод (зарезерв, по мере внедрения) |

**Не включать:** `/new`, `/events`, `/about` — дубли нижнего меню.

## 3. Inline-кнопки по состояниям

На экране: максимум **1 главное действие** + 1–2 дополнительных.

### Старт без активной поездки

- ✨ Создать поездку
- ℹ️ Как это работает

### Поездка создана

- 📌 Пример вводных (опционально)

Пользователь может сразу писать текстом — отдельная кнопка «Ввести» не обязательна.

### Бриф частично собран

- ✏️ Уточнить детали
- 📌 Показать текущий бриф

### Базовых данных достаточно (value moment #1)

Текст:

> Отлично, базовый бриф уже собран. Теперь можно подключить участников — они добавят свои пожелания, а я соберу всё в одну картину.

Кнопки:

- ✉️ Создать ссылку для участников
- 📌 Показать бриф

### Ссылка создана (value moment #2)

Текст:

> Готово — ссылка для участников создана.
>
> Теперь не нужно собирать пожелания вручную в чате: участники перейдут по ссылке, напишут вводные, а я добавлю их в общий бриф и подсвечу расхождения.

Кнопки:

- 📤 Поделиться приглашением
- 🔗 Показать ссылку
- ✅ Я отправила ссылку

**Текст для пересылки:**

> Привет! Я собираю вводные по нашей поездке.
> Перейди по ссылке и напиши, что тебе важно: даты, бюджет, перелёт, отель, климат, активности или ограничения.
> Бот добавит твои пожелания в общий бриф:
> {invite_link}

После «Поделиться» / «Я отправила»:

- ✅ Я отправила участникам
- 📌 Вернуться к брифу

### Участник подключился

- 📌 Посмотреть бриф
- ✍️ Добавить пожелания (можно сразу текстом)

### Участник добавил пожелания

- ✅ Подтвердить
- ✏️ Дополнить ещё

### Организатор: обновление от участника

- 📌 Показать обновлённый бриф
- ⚠️ Расхождения (если есть)
- 📤 Пригласить ещё

### Есть расхождения

- ⚠️ Разобрать расхождения
- ✏️ Уточнить приоритет
- 📌 Вернуться к брифу

### Бриф готов к подтверждению

См. канонические тексты: **`BRIEF_SHARING_UX_COPY.md`** (экран A).

- ✅ Подтвердить бриф
- ✏️ Дополнить ещё
- 📌 Показать бриф

### Бриф подтверждён (value moment #3)

См. **`BRIEF_SHARING_UX_COPY.md`** (экраны B, C).

- 📤 Поделиться брифом
- 📋 Текст для пересылки
- 📌 Посмотреть бриф
- ✨ Новая поездка

Не показывать PDF / публичную ссылку, пока не реализованы.

## Мои поездки — формат карточки

Предпочтительно по смыслу, не только `#номер`:

```
🏖 Греческие острова, сентябрь
Статус: ждём ответы участников
Ответили: 1 из 8
Следующий шаг: отправить ссылку участникам
```

## UX-валидация (кратко)

| Критерий | Оценка | Комментарий |
|----------|--------|-----------|
| Разделение уровней навигации | ✅ | Нативно для Telegram, снижает когнитивную нагрузку |
| Value moments (3 точки) | ✅ | Явный outcome после брифа и ссылки |
| Шаринг ссылки | ✅ | Готовый текст + «Я отправила» — понятный следующий шаг |
| Финальный бриф | ✅ | Подтверждение организатором + sharing в `main.py` |
| «Текущая поездка» | ✅ | Resume по последней активной поездке |
| Дубли в help inline | ✅ | «Мои поездки» убраны из help-keyboard |
| Обращение на «ты» | ✅ | `BOT_PERSONA.md`, tone-of-voice, тексты бота |

### Улучшения по итогам ревью

1. Приглашение: сценарий «поделиться → текст → подтверждение → ожидание ответов».
2. Помощь только через `/help`, без дубля в нижнем меню.
3. Burger: `/start`, `/help`, `/cancel` (без `/new`).
4. Участник: вход и пожелания на «ты», без лишней кнопки «ввести».
5. Уведомление организатору: акцент на обновлении брифа, не только «принято».

## Отличия от предыдущей версии бота (v1)

- Нижнее меню переименовано под новую схему; старые подписи кнопок поддерживаются как алиасы при вводе.
- Поток приглашения расширен: «Поделиться» + готовый текст + подтверждение отправки.
- Персона: женский род бота, обращение на «ты» — см. `BOT_PERSONA.md`.
